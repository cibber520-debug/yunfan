## 一、问题陈述（Problem Statement）

### 1.1 我们要解决什么问题
高考志愿填报存在**严重的信息不对称**与**不可逆的容错率**：考生用"去年的分数线填今年的志愿"是普遍现象，而每年录取位次因报考热度、招生计划、政策变化而剧烈波动。现有产品停留在"分数线大数据匹配"的**工具层**，无法给出"报什么胜率最高"的**策略层**结论。

### 1.2 问题有多大（来自数析）
- 高考报名人数约 **1300 万+/年**，志愿填报服务市场约 **10–11 亿元/年**，年增速 **7%**。
- 线上化渗透率仅 **15–20%**，付费转化率 **5–8%**，主流竞品 ARPU **200–500 元**。
- 新高考（3+1+2 / 3+3）已覆盖 **29 省**，2025 年全面落地，**高一选科直接决定可报专业范围**——采集阶段的选科校验失误将直接导致推荐结果系统性失真。

### 1.3 本 PRD 的核心命题
**在 MVP 阶段，把"信息采集 → 意向唤醒 → 智能推荐"这条主链路做透、做严谨**——以"省位次"为唯一稳定的跨年匹配主键，以"冲稳保垫"四级梯度 + 可解释降级策略为高容错率机制，为后续博弈引擎、专家兜底、职业规划前置打好数据基石。

## 二、产品目标（Product Goals，3 个清晰、正交的目标）

| # | 目标 | 衡量锚点 | 正交性说明 |
|---|------|----------|------------|
| **G1** | **采集高完成、低疲劳**：让用户在 ≤5 分钟内、零专业门槛地填完全部必填信息，Wizard 完成率 ≥ 85% | 完成率、平均耗时、弃填率 | 解决"输入难"，与 G2/G3 不重叠 |
| **G2** | **推荐高准确、可解释**：基于省位次 + 等位分转换，输出可解释、可复核的冲稳保垫梯度，保底志愿覆盖率 100%（每位用户 ≥3 个"垫"档志愿） | 保底覆盖率、推荐采纳率、零滑档率 | 解决"推荐准"，独立于 G1/G3 |
| **G3** | **容错高兜底、可降级**：当用户处于分数断层/边缘、喜好过窄时，系统能主动降级并明确告知风险，绝不输出"假精确"的空结果 | 降级触发率、降级后满意度、空结果率=0 | 解决"不滑档"，与 G1/G2 互补 |

> 三个目标分别锚定**输入侧、算法侧、异常侧**，互不替代。

| 指标 | 定义 | MVP 目标值 | 数据来源 |
|------|------|-----------|----------|
| 采集完成率 | 进入 Wizard 并完成必填的用户占比 | ≥ 85% | 埋点 |

| 降级接受度 | 触发降级后用户继续使用的比例 | ≥ 70% | 埋点 |

## 四、目标用户与核心痛点（User Personas & Pain Points）

### 4.1 用户画像（来自瑞思，已验证）
| 角色 | 细分维度 | MVP 相关性 |
|------|----------|-----------|
| **考生** | 按分数段（高/中/低）、地域（新高考省/老高考省/高考大省）、决策心理（依赖型/自主型/焦虑型） | 直接使用者，采集主入口 |
| **家长** | 按家庭背景（资源型/普通型/县域型）、付费意愿（高/中/低）、三大恐惧（滑档恐惧/调剂恐惧/信息滞后恐惧） | 决策者/付费方，影响权重矩阵 |
| **教师** | 辅助角色（班主任/升学指导） | MVP 暂不做教师端（见 Non-goals） |

### 4.2 核心痛点（瑞思 100% 验证）
1. **用去年分数线填今年志愿**（信息不对称动态变化）—— 用户无法追踪省份/宏观/招生政策实时波动。
2. **各 APP 推荐结果趋同**（同质化）—— 均停留在"分数线匹配"，千人一面加剧扎堆滑档。
3. **容错率极低是付费核心驱动力** —— 滑档/调剂影响一生，用户愿为"安心"付费。

### 4.3 PRD 必须回答的设计命题
- **如何引导无痛输入**：长表单 → 分步式 Wizard；位次由总分**自动反查补全**，减少手动操作。
- **如何提供高容错率推荐**：以"省位次"为稳定主键 + 冲稳保垫四级梯度 + 主动降级策略，杜绝"假精确"。

## 五、用户故事（User Stories，3–5 个场景）

**US-1（考生·新高考·自主型）**
> 作为广东（3+1+2）考生，我选科为"物理+化学+生物"，考了 612 分。我希望输入省份+总分后，系统自动反查我的省位次、自动限定可选专业必须包含"物理+化学"，并给出冲稳保垫四档院校专业组，且"临床医学"类因我选科符合而被纳入。

**US-2（家长·高考大省·焦虑型）**
> 作为河南（老高考·理科）考生家长，孩子 580 分、省位次 4.2 万。我极度恐惧滑档，希望系统保证至少 3 个"垫"档绝对保底志愿，并明确标注每个志愿的录取概率，让我"看得见安心"。

**US-3（考生·边缘分段·喜好过窄）**
> 作为只想去"江浙沪 985 且绝不读土木"的考生，我的分数仅够普通 211。当系统发现"完全满足所有喜好"的学校为 0 时，应主动降级（先放宽院校层次，再放宽地域），并明确告知"已为你放宽至 X 条件"，而非直接给空结果或编造匹配。

**US-4（考生·新增专业·无历史）**
> 我关注的某 211 今年新增"人工智能（大类）"专业，无历史分数。系统应基于同校同大类历史数据外推一个预测位次，明确打标"新专业·预测数据·置信度低"，仅作参考，不冒充"稳"档。

**US-5（考生·特殊身份）**
> 作为符合"国家专项计划"的农村考生，我希望勾选身份后，系统自动纳入专项批次可报院校，并在计划变动时修正推荐位次，而非与普通批混算。

## 六、用户研究洞察（引用瑞思结论）

- **三大痛点 100% 验证**：信息滞后、推荐趋同、容错率极低——其中"容错率极低"是付费核心驱动力。
- **6 大蓝海需求**（本 MVP 仅"意向唤醒/信息采集"部分承接，其余入停车场）：职业规划前置化、心理支持、家庭协同决策、校友真实路径、后续衔接、教师端。
- **Kano 模型分层**（指导 MVP 取舍）：
  - 基础需求：**准确匹配**（位次→院校）—— 不做透即无价值。
  - 期望需求：**个性化推荐**（权重矩阵、喜好拦截）—— 差异化起点。
  - 兴奋需求：专家兜底 / 志愿保险 —— **本 MVP 不实现**，留作 Phase 2（见 Non-goals 与开放问题）。

## 七、竞品对比（引用竞析结论，5–7 家）

竞析结论：**7 家核心竞品全部停留在"分数线匹配"模式**，同质化严重。本产品以"位次主键 + 梯度策略 + 降级容错"切入，直击其"扎堆风险、静态数据、决策共识缺失"三大局限。

| 竞品 | 核心模式 | 选科/新高考适配 | 个性化权重 | 容错/降级机制 | 本产品差异化 |
|------|----------|----------------|-----------|--------------|--------------|
| 掌上高考 | 分数线库+院校库 | 弱 | 无 | 无 | 位次主键+梯度 |
| 夸克高考 | AI 大数据匹配 | 中 | 弱 | 无 | 可解释降级 |
| 优志愿 | 会员制匹配 | 中 | 弱 | 无 | 权重矩阵 |
| 蝶变志愿 | 冲稳保列表 | 中 | 无 | 简单 | 四级+概率 |
| 圆梦志愿 | 院校推荐 | 弱 | 无 | 无 | 同组专业组 |
| 蜻蜓生涯 | 生涯+填报 | 中 | 弱 | 无 | 采集前置 |
| 百度AI志愿助手 | 大模型问答 | 中 | 弱 | 无 | 结构化采集 |

**6 大空白机会**（竞析）：家庭决策协调、实时博弈模拟、低分段蓝海、录取后延伸、县域深度服务、反焦虑定位。本 MVP 主要承接"反焦虑定位"（可解释、可降级）+ "低分段蓝海"（保底覆盖），其余留待后续。

## 八、数据依据（引用数析结论）

- 市场规模 **10–11 亿/年**、增速 **7%**；用户基数 **1300 万+/年**；线上渗透 **15–20%**；付费转化 **5–8%**；ARPU **200–500 元**。
- 新高考 **29 省**已落地 → **采集模块必须将"选科组合 + 省份投档规则"作为一等约束**，否则推荐失真。
- 差异化数据支撑：**新高考省份最 underserved、低分段考生服务严重不足、县域渗透率极低** → MVP 保底逻辑须对低分段同样生效（垫档不可只服务高分）。

## 九、详细功能需求（字段属性 / 交互规则 / 校验逻辑）

> 约定：所有下拉枚举值来自**后端配置表**（省份表、院校表、专业目录、学科门类表），前端不硬编码。
> 关键术语：**省位次（R）** = 考生在本省该科类一分一段表中的排名（数值越小越优）。

### 9.1 模块 A：考生成绩与基本面采集（精准定位）

#### 字段设计 A

| 字段名 | 中文 | 数据类型 | 必填 | 约束条件 | 示例值 | 联动/交互规则 | 校验逻辑 |
|--------|------|----------|------|----------|--------|--------------|----------|
| `province` | 生源省份 | enum(34 省级行政区) | **是** | 必须命中省份配置表 | `广东省` | 选择后自动推导 `exam_type` 默认值，并加载该省投档规则集 | 格式：必须在配置表内；非法省抛 400 |
| `exam_type` | 高考模式 | enum(`OLD_ART`/`OLD_SCI`/`NEW_33`/`NEW_312`) | **是** | 由 province 推导默认值，用户可改；改后重渲染选科选项 | `NEW_312` | 联动 `subject_combo` 选项与可选范围 | 业务校验：若 province 已锁定为老高考省，用户改选 `NEW_*` 须二次确认并提示"该省非新高考" |
| `subject_combo` | 选科组合 | string / array(科目码) | **是** | 组合须合法（见 9.1.1 拦截规则） | `["PHY","CHE","BIO"]` | 依据 `exam_type` 动态生成可选科目与选项数 | 非法组合拦截（9.1.1）；与意向专业选科要求冲突时告警（9.2） |
| `total_score` | 总分 | int | **是** | 0 ≤ 值 ≤ 该省该科类满分（通常 750） | `612` | 输入后**自动反查** `province_rank` 与 `rank_segment` | 范围校验；超出满分报错 |
| `score_by_subject` | 单科成绩 | object(map 科目→分数) | 选填（必填科目强制） | 单科 ≤ 单科满分；用于专业单科要求校验 | `{"PHY":89,"CHE":95,"BIO":91,...}` | 仅采集 `exam_type` 对应科目 | 单科超满分报错；与 `total_score` 逻辑一致性抽检 |
| `province_rank` | 省位次（核心） | int | **是** | 1 ≤ R ≤ 该省该科类考生总数 | `15230` | **系统根据 `total_score` + 当年一分一段表自动反查填充**；用户可手动覆盖（覆盖后标"手动"） | 反查值与手动值偏差 >±3% 时提示"位次与分数不匹配，请核对" |
| `rank_segment` | 一分一段区间 | string(自动) | 自动 | 由 `total_score` 反查 | `612分 对应 15000–15300 名` | 只读展示 | 无 |
| `special_identity` | 特殊身份/加分项 | multi-enum | 选填 | `[国家专项,地方专项,高校专项,强基计划意向,艺术体育类,少数民族加分,烈士子女,退役军人,无]` | `["国家专项"]` | 勾选后联动展示 `bonus_score`、专项批次志愿 | 与普通批不可同时占同一志愿位（业务规则） |
| `bonus_score` | 加分值 | int | **条件必填**（选了加分项时） | 0 ≤ 值 ≤ 该省法定上限（通常 ≤20） | `20` | 仅当 `special_identity≠[无]` 显示 | 超法定上限报错 |
| `art_sport_category` | 艺体类具体类别 | string | 条件必填 | 当 `special_identity` 含艺术/体育类时必填 | `美术类` | 联动专业目录（仅艺体类专业可选） | 类别与可选专业范围一致 |
| `batch_intent` | 意向批次 | enum(本科提前/本科一批/本科二批/专科…) | 选填 | 依 province 批次设置 | `本科一批` | 默认按分数自动建议 | 与 `total_score` 达线情况一致性提示 |

#### 9.1.1 选科非法组合拦截规则（开发级）

| exam_type | 合法规则 | 非法示例 | 拦截提示 |
|-----------|----------|----------|----------|
| `OLD_ART`（老文） | 政+史+地（或本省文科统考科目） | 选了"物理" | "老高考文科不可选物理，请切换为理科或新高考模式" |
| `OLD_SCI`（老理） | 理+化+生（或本省理科统考科目） | 选了"政治"作为主科 | "老高考理科不含该组合，请核对" |
| `NEW_33`（3+3） | 6 选 3（物化生政史地），无首选限制，不可重复 | 只选 2 门 / 重复选"物理"两次 | "3+3 须恰好选 3 门不同科目" |
| `NEW_312`（3+1+2） | 首选 2 选 1（物理/历史）+ 再选 4 选 2（化学生物政治地理） | 同时选"物理+历史" / 再选只选 1 门 / 再选选了"物理" | "3+1+2 须 物理/历史 二选一，再从其余 4 科选 2 门" |

> **拦截时机**：前端实时校验（输入即报错）+ 后端二次校验（提交时 400）。**专业选科要求冲突**（如用户未选"物理+化学"却想报临床医学）在 9.2 模块以"黑名单式拦截 + 灰显不可选"处理。

### 9.2 模块 B：目标喜好与权重矩阵（意向唤醒）

#### 字段设计 B

| 字段名 | 中文 | 数据类型 | 必填 | 约束 | 示例值 | 交互规则 | 校验逻辑 |
|--------|------|----------|------|------|--------|----------|----------|

| `major_specific_pref` | 具体专业偏好 | multi-enum | 选填 | 须属于所选门类（否则提示） | `["临床医学","计算机科学与技术"]` | 受 `major_category_pref` 过滤 | 专业不在已选门类 → 提示先选门类或自动补充 |
| `major_blacklist` | 绝对不读专业黑名单 | multi-enum | 选填 | 拦截级 | `["土木工程","市场营销"]` | 推荐结果中**强制剔除**并灰显不可加 | 与 `major_specific_pref` 冲突 → 报错"同一专业既想读又拉黑" |
| `weight_protect_major` | 保专业权重 | int(0–100) | **是** | 三权重归一（和=100 或相对比例） | `50` | **三滑块联动**：拖动其一，另两者按比例回填，实时预览分布 | 三者之和≠100 → 不允许进入推荐 |
| `weight_protect_school` | 保学校权重 | int(0–100) | **是** | 同上 | `30` | 同上 | 同上 |
| `weight_rush_city` | 冲城市权重 | int(0–100) | **是** | 同上 | `20` | 同上 | 同上 |
| `risk_appetite` | 风险偏好 | enum(`CONSERVATIVE`/`BALANCED`/`AGGRESSIVE`) | 选填 | 默认 `BALANCED` | `BALANCED` | 影响冲稳保垫区间宽度（见 10.3） | — |

#### 9.2.1 权重矩阵交互（产品实现要点）
- 三个滑块**联动归一**：用户拖动"保专业"至 50，系统按当前比例自动缩放另两项使其和为 100；提供"一键均衡（33/33/34）"与"保专业优先 / 保学校优先 / 冲城市优先"三个预设。
- **实时预览**：滑块变动即时重算"冲稳保垫"数量分布（无需提交），降低决策焦虑（呼应竞析"反焦虑定位"空白）。
- 权重如何影响排序：最终推荐列表按 `score = w_major·专业契合度 + w_school·院校契合度 + w_city·城市契合度` 对各候选打分后排序；黑名单专业 `score=−∞` 强制剔除。

## 十、业务规则与算法推荐引擎逻辑（开发级）

### 10.1 分流规则（Routing by Province）

系统依据 `province` 加载**省份投档规则集 `RuleSet(P)`**，决定推荐引擎的行为参数：

| 参数 | 说明 | 取值示例 |
|------|------|----------|
| `volunteer_mode` | 投档模式 | `PARALLEL`（平行志愿，多数省）/ `SEQUENTIAL`（顺序志愿，提前批部分） |
| `unit_type` | 志愿单位 | `MAJOR_GROUP`（院校专业组，3+1+2/3+3 多数）/ `MAJOR_SCHOOL`（专业+院校，辽冀渝等）/ `MAJOR`（老高考院校+专业） |
| `adjust_allowed` | 是否服从调剂 | `true`（专业组内调剂）/ `false`（专业+院校无调剂） |
| `tie_break` | 同分排序规则 | 省考试院规定（如"语数外总分→单科"），用于边界位次判定 |
| `batch_config` | 批次与志愿数量 | 如"本科批 40 个专业组志愿" |

> **分流效果**：`unit_type=MAJOR_GROUP` 时，推荐与拦截均以"专业组"为最小单位（组内是否满足选科要求、组内是否含黑名单专业）；`unit_type=MAJOR_SCHOOL` 时以"具体专业"为单位且无调剂（滑档风险更高，保底逻辑须更激进）。

### 10.2 位次转换算法（Rank Conversion，核心）

**主键选择**：以**省位次 R** 为跨年唯一稳定匹配键（分数受试题难度年波动大，位次稳定）。

**等位分法（Equivalent Score，主用）**：
```
输入：考生今年位次 R，目标历史年 Y（通常为 Y-1）
1. 载入 Y 年该省该科类「一分一段表」 RankTable_Y
2. 在 RankTable_Y 中找到 位次 ≈ R 对应的分数 S_equiv
   S_equiv = reverseLookup(RankTable_Y, R)   // 二分查找最近位次
3. 输出 S_equiv 作为「等位分」，用于匹配 Y 年各校专业录取最低分
```
**线差法（Line-Difference，兜底/校验）**：
```
线差 = 考生总分 - 今年批次线
等效分 = 去年批次线 + 线差
```
> 当一分一段表缺失（数据管线未覆盖当年）时，退回线差法并**明确标注"估算，置信度低"**（呼应 G3 不输出假精确）。两种方法结果偏差 > 给定阈值时，以等位分为准并告警。

### 10.3 冲稳保垫计算逻辑（Tier Calculation）

基于考生位次 R 与候选「专业组/专业」往年录取最低位次 `lastRank`，并叠加**招生计划修正**：

**招生计划修正系数**：
```
planCur  = 今年该专业组招生计划
planLast = 去年该专业组招生计划
if planLast == 0: factor = 1.0          // 无历史不修正
else: factor = clamp(1 / (planCur/planLast), 0.8, 1.25)  // 扩招→位次放宽(系数>1)，限幅 ±20%~25%
adjustedRank = lastRank * factor
```

**四级梯队位次区间**（以 R 为基准，数值越小越优；"上浮"=位次变好/数值缩小）：

| 梯队 | 含义 | 位次区间（相对 R） | 录取概率（估） | 说明 |
|------|------|-------------------|---------------|------|
| **冲 Reach** | 跳一跳够得着 | `[R×(1−0.15), R×(1−0.10)]` | 30%–60% | 位次上浮 10%–15% |
| **稳 Match** | 大概率稳 | `[R×(1−0.05), R×(1+0.05)]` | 60%–85% | 位次 ±5% |
| **保 Safe** | 较安全 | `[R×(1+0.15), R×(1+0.25)]` | 85%–95% | 位次下浮 15%–25% |
| **垫 Cushion** | 绝对兜底 | `[R×(1+0.30), +∞)` | >95% | 位次下浮 30%+，**每位用户强制 ≥3 个** |

**风险偏好对区间的调制**（`risk_appetite`）：
- `CONSERVATIVE`：冲缩为 `[R×0.90, R×0.95]`，垫扩为 `[R×1.40, +∞]`，垫档数量下限提升至 ≥5。
- `AGGRESSIVE`：冲扩为 `[R×0.80, R×0.85]`，垫缩为 `[R×1.25, +∞]`。

**匹配判定伪码**：
```
for each candidate in eligible(province, exam_type, subject_combo):   // 已通过选科/黑名单硬过滤
    lastRank   = getLastAdmitRank(candidate, province, Y-1)
    adjRank    = lastRank * planAdjustFactor(candidate, province)
    tier       = classify(adjRank, R, tiers(risk_appetite))
    if tier == null: continue
    if not passPreferenceFilters(candidate, prefs): continue
    add(candidate, tier, probabilityEstimate(adjRank, R))
```

### 10.4 新增专业推荐逻辑（无历史分数的外推）

```
输入：某专业组/专业 今年新增，无 lastRank
1. sameGroup = 同院校同专业组内 有历史数据的其他专业
   if sameGroup 非空:
       baseRank = median([m.lastAdmitRank for m in sameGroup])
       conf = 0.6; label = "新专业·同组外推"
   else:
       schoolMedian = 该校整体录取位次中位数
       baseRank = schoolMedian * categoryHeatFactor(新专业所属学科门类)  // 热门门类×0.8，冷门×1.2
       conf = 0.4; label = "新专业·院校外推"
2. 仅纳入「冲」或「保」参考，禁止直接标「稳」
3. 前端强制打标 label + "置信度低·预测数据"，并在志愿表注明
4. 若既无同组也无该校历史（全新院校/数据不足）→ 放入「待定·需专家确认」池，不自动推荐
```

### 10.5 异常与边界处理（降级策略 Degradation）

**目标：空结果率 = 0%（G3）。** 当"完全满足所有喜好"的匹配为空时，按等级主动降级，每次降级均向用户展示横幅说明：

```
result = matchWithAllPreferences(prefs)          // 全约束
if notEmpty(result): return result

// L1：放松最低院校层次
relax(min_tier_control); 
if notEmpty: return result + banner("已放宽：取消最低院校层次限制")

// L2：放松地域排斥（保留期望，移除排斥）
relax(region_reject)
if notEmpty: return result + banner("已放宽：取消排斥城市限制")

// L3：放松专业黑名单（保留，但另出提示，不强制剔除）
relax(major_blacklist, warnOnly=true)
if notEmpty: return result + banner("含黑名单专业，已为您标注，请谨慎")

// L4：扩大位次区间（冲 20% / 垫 40%）
expandTiers(reach=0.20, cushion=0.40)

// L5：极端断层——仍为空
if isEmpty: 
    return emptyList 
      + UI:"当前分数段在您的偏好下暂无完全匹配方案"
      + 引导:①手动搜索 ②专家兜底(Phase2) ③放宽偏好向导
      + 风险告知:"以下为最接近的可选方案(已忽略部分偏好)"
```

> 降级过程**全程可回溯**：用户可在结果页一键"恢复我的原始偏好"查看差异，避免"被系统偷偷改了条件"的不信任感（呼应瑞思"容错率即信任"）。

### 13.2 算法逻辑说明（开发可理解）
- **主键**：省位次 R（跨年稳定）。
- **年份归一**：等位分法（一分一段反查）为主，线差法为缺失兜底。
- **修正**：招生计划变动 factor ∈ [0.8, 1.25]。
- **梯队**：冲[R×0.85,R×0.90] / 稳[R×0.95,R×1.05] / 保[R×1.15,R×1.25] / 垫[R×1.30,+∞]，风险偏好调制宽度。
- **降级**：L1 放层次 → L2 放排斥 → L3 放黑名单(告警) → L4 扩区间 → L5 引导人工/专家，保证空结果率=0。
- **新增专业**：同组中位外推(conf 0.6) → 院校中位×门类系数外推(conf 0.4) → 否则入待定池；仅作冲/保参考，禁标"稳"。

## 十五、技术考量（Technical Considerations）
- **数据模型（核心表）**：`province_rule(省,投档模式,单位,调剂,同分规则)`、`score_segment(省,年,科类,分数,累计人数)`、`school_major_group(院校,专业组,选科要求,招生计划,往年录取位次)`、`major_catalog(专业,学科门类,选科要求)`、`user_profile / user_preference`。
- **API 需求**：`GET /rule/{province}`、`POST /rank/reverse(总分→位次)`、`POST /recommend(主链路)`、`GET /major/eligible(选科过滤)`。
- **数据管线**：一分一段表、招生计划、录取位次须**每年更新且带年份版本**；缺失年触发线差法降级（REQ-010）。
- **性能**：推荐计算单次 < 1s（候选集预过滤 + 位次区间索引）。

## 十六、Non-goals（明确不做什么，MVP 范围外）

1. **不做教师端 / 家庭协同决策**（瑞思蓝海，留 Phase 2）。
2. **不做专家真人兜底 / 志愿保险**（Kano 兴奋需求，Phase 2；本 MVP 降级仅引导，不承诺赔付）。
3. **不做博弈/热度预测引擎**（方案 C 核心，依赖多年数据沉淀，本 MVP 仅留数据接口）。
4. **不做职业规划前置 / 校友路径 / 录取后延伸**（方案 B/D，本 MVP 仅"意向唤醒"承接，不做长期规划）。
5. **不做 UGC 口碑社区**（方案 D，Phase 3）。
6. **不做跨年复读生追踪、不做 B 端学校版**。
7. **不承诺录取结果**（所有输出为概率/预测，强制免责）。

> **范围纪律**：任一 P0 新增须伴随 P1 移除或时间线延长（见开放问题 Q2）。

## 十八、待确认问题（Open Questions，真正开放、非己能答）

- **Q1（范围）**：MVP 首发的**省份覆盖范围**？是全国 29 省一次性，还是先聚焦新高考大省（粤/苏/浙/冀/辽等）跑通再扩？直接影响数据管线工作量。
- **Q2（资源）**：是否有**算法/数据工程师**投入？REQ-010/011/012 需历史录取位次数据采购与清洗，若数据获取受限需下调精度预期或调整范围。
- **Q3（数据合规）**：一分一段表、招生计划、录取位次的数据**来源与合规授权**（教育部/考试院公开数据 vs 第三方采购）？影响上线时间与法律风险。
- **Q4（兜底边界）**：降级 L5 仍为空时，是否接入"专家兜底"（Phase 2）还是仅引导手动搜？涉及免责与商业承诺边界。
- **Q5（权重默认值）**：三权重初始默认采用"均衡 33/33/34"还是依用户分数段智能预设？需用户研究补充或 A/B。
- **Q6（概率口径）**：冲稳保垫的"录取概率"是否对外展示具体数值？展示可增强信任但也可能被误读为承诺，需法律+产品共识。

## 附录 A：术语表
- **省位次 R**：考生在生源省该科类一分一段表中的排名，数值越小越优，本引擎跨年匹配主键。
- **等位分**：将今年位次映射到历史年一分一段表所得分数，用于跨年比较。
- **专业组**：新高考"院校专业组"投档单位；组内可调剂。
- **冲/稳/保/垫**：基于位次相对区间的四级推荐梯度。
