## 3. 优先级评估结论

### 3.1 整体排序合理性评估

PRD 的优先级分布（P0×13 / P1×5 / P2×2）整体**合理**，核心链路「采集 → 意向 → 推荐 → 兜底 → 展示」的必需件基本都在 P0，符合 MVP「做透主链路」的命题（PRD 1.3）。但存在三处需修正/澄清：

1. **REQ-005（院校层次偏好）被标 P0 却未进里程碑**（见 §2 缺口说明）—— 实际上它依赖位次预筛，属采集偏好件，建议保留 P0、补入 M1/M2。
2. **REQ-015（降级/兜底 L1–L5）被标 P1，但它是 G3「空结果率=0」的唯一实现件** —— 它的 L1–L2（放层次/放排斥）是保底逻辑硬依赖，建议**至少将 L1–L2 提为 P0 内核**，L3–L5 维持 P1。否则空结果率=0 这一核心 KPI 会落在 P1 上，与「MVP 必须做透容错」自相矛盾。
3. **REQ-008（权重矩阵联动交互）是 13 个 P0 中最偏「差异化增强」而非「核心链路必需」的一条** —— 算法层按固定/预设权重即可产出冲稳保垫，三滑块实时预览属体验增强。建议视上线压力可降级（见 §3.3）。

### 3.2 依赖关系梳理（含 PRD 已点明的链路）

| 上游（前置） | 下游（依赖方） | 依赖性质 |
|--------------|----------------|----------|
| 数据管线（一分一段表/招生计划/录取位次） | REQ-003、REQ-010、REQ-012 | 数据主权：无数据则全算法失效 |
| REQ-002（选科采集/拦截） | REQ-013（专业选科匹配校验） | 数据模型：需合法 `subject_combo` 才能校验专业选科要求 |
| `major_catalog`（专业选科要求表） | REQ-013、REQ-007 | 参考数据：黑名单与灰显依赖目录 |
| REQ-010（等位分） | REQ-012（冲稳保垫） | 跨年主键：等位分/位次换算框架 |
| REQ-011（招生计划修正） | REQ-012（冲稳保垫） | `adjustedRank = lastRank × factor` 直接输入梯队归类 |
| REQ-009（分流 RuleSet） | REQ-007/013/012 | 投档单位（专业组/专业）决定过滤与归类粒度 |
| REQ-005（层次偏好）→ REQ-006（地域偏好）→ REQ-007（专业偏好） | REQ-015（降级 L1/L2/L3） | 降级逐级放松的锚点来源 |
| REQ-012（冲稳保垫） | REQ-015（降级触发） | 全约束为空才触发降级 |
| REQ-012 / REQ-014 / REQ-015 | REQ-017（结果页） | 结果页是以上所有输出的组装层 |
| REQ-010 / 012 / 014 | REQ-020（置信度标注） | 预测/外推数据须带标签 |

### 3.3 P0 → P1 降级候选（供主理人「更早验证核心价值」决策）

若产品负责人希望把上线周期再压缩、优先验证「位次主键 + 冲稳保垫梯度」这一核心假设，我评估可动用的 P0 降级空间如下：

- **首选候选：REQ-008 权重矩阵「富交互」部分（3.5pd）**
  - 保留：后端按预设权重（均衡 33/33/34 或依分数段智能预设，呼应 Q5）计算，结果页正常输出冲稳保垫。
  - 降级到 P1：自由拖动三滑块 + 实时预览分布 + 三联动归一动画。
  - 理由：权重是「差异化起点」而非「核心链路必需」，用户研究尚未确定默认权重（Q5 开放），先做预设即可验证推荐准确性，富交互留灰度后迭代。
  - 影响：省 ~2pd 前端 + 提前 M3 出口。

- **次选候选：REQ-005 的「手动控制最低层次（min_tier_control）」子项（含于 1.5pd）**
  - 保留：默认按位次预筛可触及层次（`school_ownership=PUBLIC` 剔除民办）。
  - 降级到 P1：用户手动设 `min_tier_control` 下限 + 其作为降级 L1 锚点的 UI 暴露。
  - 理由：降级 L1 可先以「系统自动取消层次限制」实现，无需用户显式控制件。

- **不推荐降级的核心 P0（坚守）**：REQ-001/002/003/007/009/010/012/013/016/017/020。这些任一切掉都会破坏 G1/G2/G3 中至少一项核心命题（尤其 REQ-010 等位分、REQ-012 冲稳保垫、REQ-013 选科校验——新高考失真防线）。

> 结论：在不牺牲核心链路的前提下，**最多可从 P0 释放约 3.5–4 人日**（主要源于 REQ-008 富交互降级 + REQ-005 手动控制件降级），对整体周期影响有限（约 −0.5 周）。真正缩短周期的主要杠杆是**砍 P1/P2 与扩展团队**（见 §4）。

## 4. 关键路径分析 & 团队配置 & 最快上线路径

### 4.1 关键路径（Critical Path）

```
[数据管线 ingestion] ──(外部依赖/最大风险)──┐
                                            ↓
[REQ-009 分流 RuleSet] → [REQ-010 等位分] → [REQ-011 计划修正]
                                            ↓
                                     [REQ-012 冲稳保垫+概率]  ← 算法内核，~11pd，关键路径最重段
                                            ↓
                                     [REQ-015 降级 L1–L5]
                                            ↓
                            [REQ-017 结果页 + REQ-020 免责]
                                            ↓
                                      [M5 灰度 + KPI 验证]
```

- **关键路径最重段 = 算法内核（REQ-010 → REQ-011 → REQ-012）**，约 11 人日，全部压在算法 + 后端，且**串行依赖数据管线质量**。这是全项目进度的「咽喉」。
- 采集/Wizard 链（REQ-001~008, 013, 016）虽长（~25pd 偏前端），但可与算法链**并行**，不属关键路径（前提是 W1–W2 数据管线 stub + 接口契约先定）。

### 4.3 团队配置建议

| 配置 | 构成 | 适用场景 | 预估周期（59.5pd） |

### 4.4 最快上线路径（核心链路优先）

若主理人选择「先验证核心价值、非核心后置」，建议以下裁剪（在 B 配置下）：

**保留（核心链路，约 43.5pd）**：全部 13 个 P0 中——
- 必留：001,002,003,007,009,010,012,013,016,017,020（11 项硬核心，约 36.5pd）
- REQ-008 降级为「预设权重版」（保留 ~1.5pd，砍富交互 ~2pd）
- REQ-005 降级为「默认预筛版」（保留 ~1pd，砍手动控制件 ~0.5pd）
- REQ-015 **L1–L2 提为 P0 内核**（约 2pd，保空结果率=0）

**砍/延后（~16pd）**：REQ-004（特殊身份，2pd，可后置，不影响主流考生）、REQ-006（地域偏好，2.5pd，先用全国不限地域）、REQ-011（计划修正，2.5pd，首版 factor=1.0 不修正，靠等位分兜底）、REQ-014（新增专业外推，3pd，首版入待定池不自动推）、REQ-018（风险偏好，1pd）、REQ-019（政策雷达，3pd）、REQ-015 的 L3–L5（2pd，首版仅 L1–L2）。

**最快上线周期：B 配置下 ≈ 5 周**（W1–W5），可赶在更早上线灰度、用真实用户验证「位次主键 + 冲稳保垫」假设，再于下一迭代补回 P1/P2。

> 注意：砍 REQ-011（计划修正）会降低精度（扩招/限招不修正），但 PRD 已给 factor∈[0.8,1.25] 限幅，首版 factor=1.0 是合理降级；砍 REQ-004 会影响专项计划考生（Q5 用户群），建议至少保留「国家专项」最简通道。

| R5 | **权重默认值未定**（Q5） | REQ-008 交互与推荐排序 | 🟡 低中 | ①先上线预设（均衡/保专业优先）；②灰度期 A/B 或用户研究补充 |

### 5.2 资源瓶颈

- **算法/数据工程师是首要瓶颈**：REQ-010/011/012/014 需历史录取位次采购与清洗（Q2），且算法工程师通常比前后端更稀缺。**缓解**：用「限定省份范围」（R1 策略）为算法减负；数据清洗评估是否可外包/分包；关键路径上优先保障算法工程师不被会议/联调占用。
- **数据获取及时性**：外部依赖（考试院公开 vs 第三方采购）是非团队可控项，**必须在 M1 前（即现在）启动**（R1）。这是比人头更硬的风险。
- **前端在 G1 上是次瓶颈**：Wizard + 结果页 ~9pd 纯前端，B 配置（2 前端）可解。

### 5.3 缓冲策略（每里程碑）

- M1 留 **0.5 周缓冲**给数据管线（最高风险）；若数据迟到，M1 先以「Mock 一分一段表 + 线差法」跑通链路，真实数据到位后切换。
- M3 留 **0.5–1 周缓冲**给算法精度调参；若精度不达标，启动 R2 规则驱动降级。
- 全程保留 **M5 末尾 1 周**作为集成/灰度缓冲，应对季节窗口压力。

## 7. 利益相关者沟通要点

### 7.1 高管版（战略对齐 / 业务影响 / 关键决策）

- **战略定位**：从「分数线查询工具」升级为「决策层策略顾问」，直击 7 家竞品同质化的空白（位次主键 + 梯度策略 + 可解释降级）。
- **市场窗口**：高考产品强季节性，下一个填报季约 2027-06，是硬 Deadline；当前 2026 年数据已可得，应趁热启动。市场 10–11 亿/年、增速 7%、ARPU 200–500 元。
- **需高管决策的三件事**：①**省份首发范围**（全国 29 省 vs 新高考大省聚焦，直接决定数据工作量与上线速度，Q1）；②**数据来源与合规授权**（公开 vs 采购，影响法律与成本，Q3）；③**资源投入**（是否给 2 前端 + 1 算法，影响周期 8→7 周）。
- **核心价值假设待验证**：用最快 5 周核心链路灰度，验证「位次主键 + 冲稳保垫」是否真能提升推荐采纳率（≥60%）与保底覆盖（100%）。

### 7.2 工程版（技术细节 / 时间线 / 依赖）

- **时间线**：M1 W1–3 → M2 W3–5 → M3 W4–7（关键路径，算法内核）→ M4 W6–8 → M5 W8–9；4 人配置约 7 周。
- **关键路径**：数据管线 → REQ-010→011→012（算法 ~11pd，咽喉）→ REQ-015 → REQ-017/020。
- **接口契约（W1 前必定）**：`POST /rank/reverse`、`POST /recommend`、`GET /major/eligible`，以及 `province_rule`/`score_segment`/`school_major_group`/`major_catalog` 四张核心表结构。
- **最高风险**：数据管线（R1），需 M1 前启动获取；算法精度（R2）首版规则驱动、概率谨慎展示。
- **依赖提醒**：REQ-015（降级）依赖 REQ-005/006/007/012；REQ-013 依赖 REQ-002 合法选科 + `major_catalog`。

### 7.3 设计版（体验目标 / 动线 / 信任）

- **体验北极星**：G1 采集完成率 ≥ 85%、耗时 ≤ 5 分钟——靠 7 步渐进披露 Wizard + 位次自动反查（用户只核对不输入）+ 高级字段默认折叠实现。
- **反焦虑设计**：权重矩阵实时预览、冲稳保垫四栏 + 概率 + 置信度、降级横幅「已为你放宽至 X」——直接承接竞析「反焦虑定位」空白。
- **信任设计（合规必做）**：所有预测/外推数据强制置信度标签（REQ-020）；降级全程可回溯「一键恢复原始偏好」，避免「被偷偷改条件」的不信任（呼应瑞思「容错率即信任」）。
- **无障碍**：滑块支持键盘/语音，关键拦截不依赖纯颜色（WCAG AA）。
